What is Stashing in Git?
    Git Stashing means temporarily saving your uncommitted changes without creating a commit.

    It allows you to switch to another branch, work on something else, and later restore your unfinished changes.

    Real-Time Example
    Suppose you are developing a Order Management Application.

    You have two branches:
    - master – Main application
    - order-service – Developing order service functionality
    You are working on order-service and have modified docs.txt, but your work is not completed.

    Suddenly, you need to switch to master to fix a bug.

    Instead of committing incomplete code, you can stash your changes.

3.1 Switch to order-service branch 
git switch order-service 

3.2 Do changes in docs.txt 
"Order Service will receive orders from customers.\nOrders will be processed later."

3.3 stash the order-service. Do temporarily save the order-branch files.
git stash 

3.4 switch to master 
git switch master 

3.5 Do changes README.md 

3.6 Stage README.md 
git add README.md 

3.7 Commit README.md 
git commit -m "some content fixed in README.md"

3.8 switch to order-service 
git swich order-service 

3.9 list stashed content 
git stash list 

Important Git Stash Commands
Command	Purpose
git stash	        Temporarily save changes
git stash list	    List all saved stashes
git stash apply	    Restore changes without deleting stash
git stash pop	    Restore changes and remove stash on success
git stash drop	    Delete a saved stash
git stash clear	    Delete all stashes
git stash -u	    Include untracked files in stash

Difference Between Commit and Stash
**Git Commit**	                                        **Git Stash**
Permanently records a snapshot in repository history	Temporarily saves unfinished changes
Has a commit message	                                Can have an optional stash message
Appears in normal git log history	                    Appears in git stash list
Used for completed units of work	                    Used for temporarily setting aside work

Git Fetch and Rebase – Explanation with Examples
    Let's understand these two commands using a real-world team development scenario.

    Suppose you and your colleague are working on the same project using GitHub.
    - You are working on your local computer.
    - Your colleague is working on another computer.
    - Both are working on the same GitHub repository.
    - Your colleague has pushed new commits to GitHub.
    - You want to get those changes and integrate them into your local branch.
    This is where fetch and rebase are useful.

    1. What is Git Fetch?
    Definition: git fetch downloads the latest commits and changes from a remote repository without automatically merging them into your current local branch.

    Command: git fetch origin

    Here:
        - git fetch – Downloads remote updates.
        - origin – Default name of the remote repository (usually GitHub).

    Example
        Initially, your local repository and GitHub have the same commits.
        Before fetch 
            Local   A → B → C
            GitHub  A → B → C → D → E

        git fetch origin

        Local branch A → B → C
        Remote tracking branch A → B → C → D → E

        Notice that your local branch is still at C. Fetch does not automatically integrate D and E into your working branch.

        Useful fetch commands
            # Fetch updates from GitHub
            git fetch origin

            # Fetch all remote branches
            git fetch --all

            # View remote branches
            git branch -r

            # View all local and remote branches
            git branch -a

        2. What is Git Rebase?
        Definition: Git rebase moves your local commits on top of the latest commits from another branch.

        In simple words, it updates your branch by replaying your local commits after the latest remote commits.
        Example
        Suppose the repository has this history:
            Before rebase
                A - B - C           Remote 
                    B - D - E       Local 
                    
            Remote has A → B → C. Your local feature branch has A → B → D → E.

            After rebase
                A - B - C - D - E 

        Rebase command
            git rebase origin/main

        Explanation:
            - git rebase – Replays your local commits on top of another branch.
            - origin/main – Updated remote-tracking branch.

        3. When to use Fetch and Rebase?
        Situation	                                    Command	                    Purpose
        Check latest remote changes	                    git fetch origin	        Download remote updates
        Inspect remote branches	                        git branch -r	            List remote branches
        Integrate remote changes with linear history	git rebase origin/main  	Replay local commits
        Integrate remote changes with merge history	    git merge origin/main	    Merge remote changes

        4. Complete Practical Example
        Suppose you are working on feature-branch and want to update it with the latest changes from GitHub's main branch.

            # Step 1: Check current branch
            git branch

            # Step 2: Fetch remote changes
            git fetch origin

            # Step 3: Switch to feature branch
            git switch feature-branch

            # Step 4: Rebase onto updated remote main
            git rebase origin/main

            # Step 5: Check commit history
            git log --oneline --graph

        If there are conflicts during rebase:
            # Resolve conflicts in the affected files

            # Stage resolved files
            git add .

            # Continue rebase
            git rebase --continue

Git Tags and Releases – Explanation with Examples
    Let's understand Git Tags and Releases using a real-world software development example.

    Suppose you are developing a Student Management Application.

    You have completed development and testing of version 1.0. Later, you add new features and release version 2.0.

    How do you identify which commit represents version 1.0 or version 2.0?

    This is where Git Tags and Releases are useful.
    1. What is a Git Tag?
    Definition: A Git Tag is a label attached to a specific commit in a Git repository.

    It helps identify important points in the project's history, such as software versions or releases.

    For example:
    - v1.0 – First stable version.
    - v1.1 – Bug fixes.
    - v2.0 – Major feature update.
    - v2.1 – Minor improvements.
    Example
    Suppose your commit history looks like this:
    A → B → C → D → E → F
            ↑           ↑
          v1.0        v2.0


    Here:
        - Commit C represents version 1.0.
        - Commit F represents version 2.0.
    Tags help you identify these important commits easily.
    2. Types of Git Tags
    Git provides two types of tags.
    A. Lightweight Tag
        A lightweight tag is simply a name pointing to a specific commit.

        Command:
        git tag v1.0


    This creates a tag named v1.0 for the current commit.
    B. Annotated Tag
        An annotated tag stores additional information, such as:
        - Tag creator
        - Date
        - Tag message
        - Tag name
        Command:
        git tag -a v1.0 -m "Version 1.0 Release"


        Here:
        - -a – Creates an annotated tag.
        - v1.0 – Tag name.
        - -m – Tag message.

    Recommended
    Annotated tags are generally preferred for official releases.

    3. Important Git Tag Commands
        Command	Purpose
        git tag	List all tags
        git tag v1.0	Create lightweight tag
        git tag -a v1.0 -m "Release"	Create annotated tag
        git show v1.0	Display tag details
        git tag -d v1.0	Delete local tag
        git push origin v1.0	Push a specific tag to GitHub
        git push origin --tags	Push all local tags

        Tag a Specific Commit
        git tag -a v1.0 abc123 -m "Version 1.0 Release"


        Here, abc123 is the commit ID.
    4. What is a Git Release?
        Definition: A Git Release is a published version of your software associated with a Git tag.

        GitHub provides a Release feature that allows developers to publish software versions with additional information.

        For example, your Student Management Application has reached version 1.0.

        You can publish a GitHub Release containing:
        - Version number: v1.0
        - Release title: Student Management Application – Version 1.0
        - Release description: Features included in this version.
        - Source code ZIP file.
        - Source code TAR file.
        - Downloadable application packages, if provided.

    How to Create a GitHub Release
        1. Open your GitHub repository.
        2. Click Releases.
        3. Click Create a new release.
        4. Select or create a tag, such as v1.0.
        5. Enter the release title.
        6. Add release notes.
        7. Click Publish release.
        GitHub Releases are built around Git tags.
        5. Difference Between Git Tags and Releases
        Git Tag	                            Git Release
        Identifies a specific commit	Publishes a software version
        Created using Git commands	    Usually created through GitHub UI or API
        Contains a tag name	            Contains tag, title and release notes
        Exists in Git repository	    Is a hosting-platform feature
        Example: v1.0	                Example: Student App Version 1.0

        Remember: A Git Tag is a marker in Git history. A Git Release is a published version of the software based on that marker.
        6. Practical Lab Example
        Let's assume you have completed the first version of your application.
        # Step 1: Check commit history
        git log --oneline

        # Step 2: Create an annotated tag
        git tag -a v1.0 -m "First stable release"

        # Step 3: List all tags
        git tag

        # Step 4: View tag details
        git show v1.0

        # Step 5: Push tag to GitHub
        git push origin v1.0


        Now your GitHub repository has the v1.0 tag.

        You can use this tag to create a GitHub Release.

Git Cherry-Pick – Explanation with Examples
Let's understand Cherry-Pick using a real-world team development scenario.
1. What is Git Cherry-Pick?
Definition: Git Cherry-Pick allows you to select specific commits from one branch and apply those changes to another branch without merging the entire source branch.

In simple words:

You can pick only the commits you need from another branch.
2. Real-World Example
Suppose you are developing a Student Management Application.

You have two branches:
- master – Main application.
- source-branch – Development branch.
Your colleague has made three changes in source-branch:
1. Commit A – Added student registration.
2. Commit B – Added student search.
3. Commit C – Fixed login bug.
But you only need the login bug fix in your master branch.

Do you need to merge the entire source-branch?

No! You can use Cherry-Pick.

Notice:
- Registration changes are not copied.
- Search changes are not copied.
- Login bug fix is copied.
- The cherry-picked change gets a new commit ID.

3. Cherry-Pick a Single Commit
First, switch to the branch where you want to apply the change.

# Switch to master
git switch master

# Cherry-pick a specific commit
git cherry-pick abc123

Here:
- master – Destination branch.
- abc123 – Commit ID to be copied.

4. Cherry-Pick a Range of Commits
Suppose source-branch contains these commits:

You want to copy commits C, D and E into your current branch.

Command: git cherry-pick C^..E

Explanation:
Part	Meaning
C	Starting commit
C^	Parent of starting commit
..	Commit range operator
E	Ending commit

Why C^..E?

Git's range notation C^..E means commits reachable from E, excluding commits reachable from the parent of C.

Therefore, it includes C, D and E.

Important: The range is inclusive of both the starting and ending commits.
5. Complete Practical Lab
Let's assume you want to cherry-pick commits from source-branch into master.

Explanation:
Part	Meaning
C	Starting commit

..	Commit range operator
E	Ending commit

Git's range notation C^..E means commits reachable from E, excluding commits reachable from the parent of C.

Therefore, it includes C, D and E.

Important: The range is inclusive of both the starting and ending commits.
5. Complete Practical Lab
Let's assume you want to cherry-pick commits from source-branch into master.

# Step 1: View all branches
git branch

# Step 2: Switch to source branch
git switch source-branch

# Step 3: View commit history
git log --oneline

# Step 4: Note the starting and ending commit IDs

# Step 5: Switch to destination branch
git switch master

# Step 6: Cherry-pick the range
git cherry-pick <start-commit>^..<end-commit>

# Step 7: Verify commit history
git log --oneline

6. What if Cherry-Pick Causes Conflicts?
Sometimes the changes you are copying conflict with existing code in the destination branch.

Git pauses the operation.
# Step 1: Resolve conflicts manually

# Step 2: Stage resolved files
git add .

# Step 3: Continue cherry-pick
git cherry-pick --continue

To cancel the operation: git cherry-pick --abort

7. Cherry-Pick vs Merge
This is an important distinction for students.
Cherry-Pick	Merge
Copies selected commits	Integrates branch changes
Can select individual commits	Combines branch histories
Does not merge the entire source branch	Merges the source branch
Creates new commit IDs for copied commits	Usually preserves existing commit IDs

## Git – View Details of a Specific Commit

Question: Given a commit ID, how would you use Git to view the details of that specific commit, including the author, date, and commit message?

### 1. Git Command

```
git show <commit-id>
```

Example:

```
git show abc123
```

### 2. What does `git show` do?

The `git show` command displays detailed information about a specific commit.

It displays:

1. Commit ID (SHA)
2. Author name
3. Author email
4. Author date
5. Commit message
6. Files changed
7. Code changes (diff)

### 3. Example Output

```
commit abc123456789
Author: John Doe <johndoe@gmail.com>
Date:   Fri Oct 30 10:30:00 2026 +0530

    Added student registration functionality

diff --git a/student.py b/student.py
...
```

### 4. Other Useful Commands

| Command                           | Purpose                                  |
| --------------------------------- | ---------------------------------------- |
| `git log`                         | Display commit history                   |
| `git log --oneline`               | Display compact commit history           |
| `git show abc123`                 | Display specific commit details          |
| `git show --stat abc123`          | Display files changed and statistics     |
| `git show --format=fuller abc123` | Display detailed author and commit dates |

### 5. Practical Lab Steps

```
# Step 1: List commits
git log --oneline

# Step 2: Copy a commit ID

# Step 3: View commit details
git show <commit-id>
```

Lab Answer

Answer:

```
git show <commit-id>
```

This command displays the details of a specific commit, including commit ID, author, date, commit message, and changes introduced by that commit.

Remember: `git log` lists commits, whereas `git show` displays the detailed information of a particular commit.

## 10. Display Commits by Author Within a Date Range

Question: Write the Git command to display all commits made by the author `JohnDoe` between January 1, 2025 and December 31, 2025.

### 1. Git Command

```
git log --author="JohnDoe" --since="2025-01-01" --until="2025-12-31"
```

### 2. Explanation

| Option                 | Meaning                        |
| ---------------------- | ------------------------------ |
| `git log`              | Displays commit history        |
| `--author="JohnDoe"`   | Filters commits by author name |
| `--since="2025-01-01"` | Specifies the starting date    |
| `--until="2025-12-31"` | Specifies the ending date      |

### 3. Example Output

```
commit abc123456
Author: JohnDoe <john@gmail.com>
Date:   Mar 15 2025

    Added student registration

commit def456789
Author: JohnDoe <john@gmail.com>
Date:   Aug 20 2025

    Updated student details

commit ghi789123
Author: JohnDoe <john@gmail.com>
Date:   Dec 10 2025

    Fixed login functionality
```

### 4. Useful Variations

```
# Display in compact format
git log --oneline --author="JohnDoe" --since="2025-01-01" --until="2025-12-31"

# Display author and date
git log --format="%h %an %ad %s" --author="JohnDoe" --since="2025-01-01" --until="2025-12-31"
```

VTU Lab Answer

```
git log --author="JohnDoe" --since="2025-01-01" --until="2025-12-31"
```

Remember:

- `--author` → Who made the commit?
- `--since` → From which date?
- `--until` → Up to which date?
- `git log` → Display commit history.

Note: Git filters by author identity, not necessarily the GitHub username. The date filters use the commit author date.

## 12. Undo Changes Introduced by a Commit

Question: Write the Git command to undo the changes introduced by the commit with the ID `abc123`.

### 1. Git Command

```
git revert abc123
```

### 2. What does `git revert` do?

`git revert` creates a new commit that reverses the changes introduced by an earlier commit.

It does not delete the original commit or rewrite the repository history.

### 3. Example

Suppose your commit history is:

```
A → B → C → D
```

- A – Initial commit
- B – Added student registration
- C – Added student search
- D – Updated student details

You discover that commit C introduced a bug.

Execute:

```
git revert C
```

Git creates a new commit E that reverses the changes introduced by C.

Before revert

A

B

C

D

After revert

A

B

C

D

E

E = New commit reversing C

Original commit C remains in history.

### 4. Useful Variations

```
# Revert a commit
git revert abc123

# Revert without automatically committing
git revert --no-commit abc123

# View commit history
git log --oneline
```

### 5. Difference Between Git Revert and Git Reset

| Git Revert                  | Git Reset                                      |
| --------------------------- | ---------------------------------------------- |
| Creates a new commit        | Moves the branch pointer                       |
| Preserves existing history  | Can rewrite local history                      |
| Safer for shared branches   | Must be used carefully                         |
| Reverses a commit's changes | Can remove commits from current branch history |

VTU Lab Answer

```
git revert abc123
```

Explanation: This command undoes the changes introduced by commit `abc123` by creating a new commit. The original commit remains in the repository history.

Remember:

- `git revert` = Undo changes safely by creating a new commit.
- `git reset` = Move the branch pointer to an earlier commit.
